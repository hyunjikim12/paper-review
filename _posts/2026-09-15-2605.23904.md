## Summary

SkillOpt는 모델 가중치를 고정한 에이전트의 스킬 문서(skill document)를 학습 대상으로 삼아, 딥러닝 옵티마이저처럼 통제된 절차로 최적화하는 텍스트 공간 옵티마이저다. 별도의 optimizer 모델이 점수가 매겨진 실행 궤적(rollout)을 읽고 스킬 문서에 대한 추가·삭제·교체 편집을 제안하며, 편집 수 상한(textual learning rate), 검증 게이트, 기각 편집 버퍼, epoch 단위 slow/meta update로 학습을 안정시킨다.

- **기여 1. 외부 텍스트 상태 최적화로서의 스킬 학습**
  - 스킬 학습을 고정된 에이전트의 외부 자연어 상태에 대한 최적화로 정식화하고, rollout 배치, 반성 minibatch, 편집 수 상한과 스케줄, 검증 게이트, 기각 편집 버퍼, slow/meta update를 갖춘 harness 독립적 옵티마이저 제안

- **기여 2. 모델·벤치마크·harness 전반의 실증**
  - 6개 벤치마크, 7개 목표 모델, 3개 실행 방식(direct chat, Codex, Claude Code)의 52칸 모두에서 최고 또는 공동 최고와 수작업·일회성·프롬프트 최적화·스킬 진화 기준 방법 대비 우위

- **기여 3. 구성 요소 검증과 스킬 산출물의 이식성**
  - 구성 요소 ablation과 모델 간·harness 간·벤치마크 간 이식 실험으로, 가중치 갱신 없이 배포 가능한 짧고 재사용 가능한 스킬 산출물임을 확인

## Background

에이전트는 도구, 파일, 검증기를 쓰는 실행 환경(harness) 안에서 동작하며, 도메인 적응에는 가중치나 프롬프트뿐 아니라 근거 수집, 도구 호출, 도메인 규칙, 출력 형식 같은 절차의 개선이 필요하다. 스킬은 이런 절차, 도메인 휴리스틱, 도구 정책, 출력 제약, 실패 유형을 담은 자연어 문서로, 고정된 에이전트가 외부 텍스트만으로 적응하게 해 주는 인터페이스다.

- **① 가중치 적응 (fine-tuning)**
  - **방식**: 목표 도메인 데이터로 모델 가중치를 갱신
  - **한계**: 폐쇄형 프론티어 모델에는 적용할 수 없고, 공개 모델에서도 비용이 큼

- **② 수작업 스킬과 일회성 생성 스킬 (SkillsBench, SoK: Agentic Skills)**
  - **방식**: 전문가가 스킬 문서를 작성하거나 LLM이 과제 설명만 보고 한 번에 생성
  - **한계**: 목표 도메인이나 harness에서 쉽게 깨지고, 실행 피드백을 받아도 개선되지 않음

- **③ 프롬프트 자동 최적화와 에이전트 구성 탐색 (TextGrad, GEPA, ABSTRAL, EvoTest)**
  - **방식**: 실행 피드백과 궤적으로 프롬프트, 다중 에이전트 설계 문서, 시스템 구성 전체를 반성적으로 진화
  - **한계**: 프롬프트나 설계, 구성을 대상으로 하며, 검증 후 내보내 재사용하는 도메인 적응 산출물을 목표로 하지 않음

- **④ 경험 기반 스킬 구축과 진화 (Trace2Skill, EvoSkill, AutoSkill, Memp, CoEvoSkills, SkillRL)**
  - **방식**: 궤적 교훈 증류, 실패 분석 기반 스킬 폴더 수정, 스킬 지식 베이스 구축, 생성기와 검증기의 공진화, 강화학습으로 스킬을 만들고 고침
  - **한계**: 스킬 발견, 저장소 확장, 공유, 진화 탐색에 초점을 두며, 느슨하게 통제된 자기 수정이라 시작점보다 안정적으로 나아진다는 보장이 없음

네 계열은 스킬이나 프롬프트를 쓰고 고치는 방법은 제시하지만, 딥러닝 학습이 재현 가능하도록 만드는 장치인 증거의 크기, 한 번에 움직이는 폭, 검증, 갱신 방향의 누적을 스킬 편집에 적용하지 않는다. 저자들은 스킬이 적응 층이라면 스킬 자체를 어떻게 최적화해야 하는가라는 기본 질문이 비어 있다고 제기한다.

## Method

SkillOpt의 발상은 스킬 문서를 고정된 에이전트의 파라미터로 보고, 가중치 학습의 요소를 텍스트 편집에 하나씩 대응시키는 것이다. 현재 스킬로 과제들을 실행해 궤적과 점수를 모으는 것이 forward pass이고, optimizer 모델이 실패와 성공 궤적을 묶음 단위로 읽어 스킬 편집을 제안하는 것이 backward pass다. 한 스텝에 적용할 수 있는 편집 수에 상한을 두는 것이 learning rate이고, 따로 떼어 둔 selection split에서 점수가 올라야만 편집을 받아들이는 것이 validation이다. 이 대응에서 가장 중요한 지점은 편집 폭의 제한이다. 한 번에 스킬을 크게 다시 쓰면 직전 버전과의 연속성이 끊겨, 어떤 편집이 도움이 됐고 어떤 편집이 기각됐는지라는 이력이 다음 편집에 쓸모를 잃는다. 편집을 작고 검증된 단위로 쌓아야 기각된 편집을 부정적 피드백으로, epoch를 가로지르는 교훈을 momentum처럼 활용할 수 있다. 여기에 두 가지 장기 기억이 붙는데, 스킬 문서 안 보호 영역에 쓰여 배포되는 slow update와, optimizer에게만 주어지고 배포되지 않는 meta skill은 역할이 다르다.

### Problem Setup

스킬 $s$는 실행 전에 에이전트 문맥에 들어가는 자연어 정책이다. direct chat에서는 system 또는 developer 지시문 앞에 붙고, 도구 사용 harness에서는 지속적인 절차 기억이 된다. 고정된 목표 모델 $M$, harness $h$, 과제 $x$, 스킬 $s$로 실행하면 궤적 $\tau$와 점수 $r$이 나온다.

$$
(\tau(s), r(s)) = h(M, x, s), \qquad r(s) \in [0, 1]
$$

학습 분할로 후보 스킬 집합 $$C(D_{tr})$$을 만들고, selection 분할에서 가장 좋은 스킬을 고른 뒤, test 분할은 최종 보고에만 쓴다.

$$
s^\star_{sel} = \arg\max_{s \in C(D_{tr})} \frac{1}{\lvert D_{sel} \rvert} \sum_{x \in D_{sel}} r(s)
$$

$$
\mathrm{Test}(s^\star_{sel}) = \frac{1}{\lvert D_{test} \rvert} \sum_{x \in D_{test}} r(s^\star_{sel})
$$

옵티마이저 상태는 현재 스킬, 검증을 통과한 최고 스킬, 이미 평가한 스킬의 해시 캐시, epoch 단위 기각 편집 버퍼, slow/meta update 상태로 이뤄지며, 최고 스킬만 `best_skill.md`로 내보낸다.

### Backward Pass: Minibatch Reflection

각 스텝에서 목표 모델은 현재 스킬로 학습 분할의 rollout 배치를 실행하고, harness는 메시지, 도구 호출, 관측, 최종 답, 검증기 피드백을 기록한다. optimizer 모델은 이 궤적을 실패와 성공으로 나누고 각각을 반성 minibatch로 쪼개 읽는다. 저자들은 궤적 하나에서는 우연한 수정이 나오지만 여러 궤적을 묶어 보면 잘못된 출처 검색, 틀린 답 형식, 도구 결과 미검증 같은 반복적 절차 오류가 드러난다고 설명한다. 실패 minibatch는 빠진 규칙이나 교정 규칙을, 성공 minibatch는 이미 잘 되는 행동을 보존하는 규칙을 제안한다. 제안은 실패 쪽과 성공 쪽을 각각 병합한 뒤 실패 교정을 우선해 다시 병합하며, 이 과정에서 중복되거나 모순되거나 특정 예시에만 맞는 제안이 걸러진다.

### Bounded Text Updates

learning rate에 해당하는 것은 스텝 $t$에서 적용할 수 있는 최대 편집 수 $$L_t$$다. optimizer 모델이 병합된 편집 후보를 기대 효용 순으로 정렬하고 상위 $$L_t$$개만 남긴다. 저자들은 상한 없는 재작성이 유용한 규칙을 지우거나, 서로 맞지 않는 지시를 넣거나, 국소 실패에 과적합한다고 보고, 상한이 있는 갱신이 연속성을 지키면서 새 절차를 익히게 한다고 설명한다. 스케줄은 constant, linear, cosine, autonomous를 지원하며 기본값은 큰 편집에서 시작해 작은 정리 단계로 줄어드는 cosine이다. 편집은 append, insert_after, replace, delete의 네 가지 원자적 연산이고, 스텝 단위 편집은 보호된 slow-update 영역을 건드릴 수 없다.

### Validation Gate and Rejected-Edit Buffer

모든 후보 스킬은 같은 목표 모델과 harness로 selection 분할에서 평가된다. 현재 점수보다 엄격하게 높을 때만 현재 스킬이 되고, 최고 점수까지 넘으면 `best_skill.md`가 되며, 동점은 기각한다. 저자들은 그럴듯한 텍스트 진단도 실제 목표 모델에는 해로울 수 있으므로, 이 게이트가 무조건적 자기 편집을 제안하고 시험하는 최적화로 바꾼다고 설명한다. 기각된 스텝의 편집과 그로 인한 점수 하락, 관측된 실패 유형은 epoch 단위 버퍼에 쌓여 같은 epoch의 이후 반성 호출에 전달되고, optimizer는 실패한 편집을 반복하지 않고 남은 실패에 집중한다.

### Epoch-Wise Slow/Meta Update

epoch가 끝나면 같은 학습 과제들을 직전 epoch의 스킬과 현재 스킬로 각각 실행해 개선, 퇴보, 지속 실패, 안정적 성공으로 분류한다. optimizer 모델은 이 비교로 장기적 지침을 써서 스킬 문서의 보호 영역에 넣고, 이 후보도 검증 게이트를 거친다. 한편 meta skill은 어떤 편집 유형이 도움이 됐고 기각됐는지, 어떤 실패가 epoch를 넘어 남았는지를 요약해 이후 optimizer 프롬프트 앞에 붙이지만 목표 모델에는 배포되지 않는다. 저자들은 이 분리로 배포되는 스킬은 짧게 유지하면서 학습 과정은 더 풍부한 편집 이력의 도움을 받는다고 설명한다. SkillOpt는 가벼운 adapter로 harness에 연결되어, 같은 옵티마이저가 direct chat, 스프레드시트 실행, 문서 추론, 멀티모달 QA, embodied 환경, Codex나 Claude Code 실행 루프에 그대로 쓰인다.

## Experiments

SearchQA, SpreadsheetBench, OfficeQA, DocVQA, LiveMathematicianBench, ALFWorld의 held-out test 분할에서 GPT 계열 5개와 Qwen 계열 2개 목표 모델을 direct chat, Codex, Claude Code 실행 방식으로 평가한다. 기준 방법은 스킬 없음, 사람이 쓴 스킬, 일회성 LLM 스킬, Trace2Skill, TextGrad, GEPA, EvoSkill이며, 기본 optimizer는 GPT-5.5, 기본 설정은 4 epoch, rollout 배치 40, 반성 minibatch 8, 편집 수 상한 4에서 2로 줄어드는 cosine 스케줄이다.

  - **목적**: 목표 모델, harness, 채점기를 고정하고 스킬 출처만 바꿔 어떤 적응 방식이 가장 강한지 비교
  - 모델 규모와 실행 방식에 관계없이 모든 칸에서 최고 또는 공동 최고이며, 절차와 답 형식 요구가 엄격한 스프레드시트, 문서, 수학 벤치마크에서 이득이 가장 크다는 주장
  - 작은 목표 모델일수록 상대적 이득이 커서, 짧은 스킬이 가중치에 없는 절차 지식을 보충한다는 해석

  - 사람 스킬도 충분히 길다는 점에서 프롬프트 길이 효과가 아니고, 가장 작은 목표 모델에서도 앞선다는 점에서 optimizer 능력만의 효과도 아니라는 주장

  - 상한 없는 재작성과 기각 버퍼 제거 모두 성능을 낮추고, meta skill과 slow update를 함께 빼면 SpreadsheetBench에서 가장 크게 떨어져 장기 증거와 보호 영역이 지속적 절차 교훈을 지킨다는 해석

_Figure 3. epoch 체크포인트별 학습, selection, test 점수_

- **검증 게이트와 일반화**
  - **목적**: selection 분할이 고른 체크포인트가 test 성능과 맞는지 확인
  - selection 점수가 held-out test 성능을 따라가, 게이트가 selection 분할에만 맞는 스킬이 아니라 일반화되는 스킬을 고른다는 주장

- **스킬 산출물의 이식성**
  - **목적**: 한 설정에서 최적화한 스킬을 추가 최적화 없이 다른 모델 규모, 실행 환경, 인접 벤치마크에 옮겨도 쓸모 있는지 확인
  - 모든 이식에서 스킬 없음보다 높고, 특히 스프레드시트 스킬의 Codex와 Claude Code 사이 이식이 커서 학습된 규칙이 특정 harness의 명령 요령이 아니라 작업 절차라는 해석
  - 벤치마크 간 이식은 이득이 작지만 모두 양수라, 스킬이 벤치마크 형식 암기가 아닌 수학 절차를 담는다는 주장

  - **목적**: 이득이 강한 프론티어 optimizer에서 오는 지식 증류인지, 최적화 루프 자체에서 오는지 구분
  - 강한 optimizer가 모든 칸에서 더 크게 올리지만, 목표 모델과 같은 optimizer도 이득의 상당 부분을 회복해 루프 자체가 기여한다는 주장

  - 최종 스킬이 짧고 수락된 편집이 적어 게이트가 대부분의 제안을 걸러낸다는 해석

## Limitations & Thoughts

- **"52칸 모두 최고"라는 주장의 크기**
  - Table 1에서 칸마다 SkillOpt와 가장 좋은 기준 방법의 차이를 계산하면 1칸은 동률(GPT-5.4-mini LiveMath), 10칸은 1점 미만, 19칸은 2점 미만이고 중앙값은 약 2.5점
  - 반복 실행, 표준편차, 유의성 검정이 없어 차이가 작은 칸의 순위는 한 번의 실행 변동 안에 있을 수 있음

- **헤드라인 수치와 기본 설정의 관계**
  - Table 1의 GPT-5.5 direct chat 결과 가운데 SearchQA 87.3과 SpreadsheetBench 80.7은 Table 2(e)의 constant 스케줄 결과와, LiveMath 66.9는 Table 2(d)의 lr=8 결과와 같고, 본문이 기본값이라 한 cosine·lr=4 결과(Table 3의 87.1, 77.5, 61.3)보다 높음
  - ablation이 test 점수로 보고되는데, 벤치마크별 설정을 selection 분할로 골랐는지 본문에 없음
  - 같은 lr=4 설정이 본문과 Table 2(d)에서는 86.5, 78.2, 56.5, Table 3에서는 87.1, 77.5, 61.3으로 다르고, 학습 데이터 양 실험의 분할 비율도 Table 2 캡션은 4:1:5, 부록은 2:1:7로 어긋남

- **검증 게이트가 test를 따라간다는 주장의 반례**
  - Figure 3의 LiveMath에서 selection best는 마지막 체크포인트에서 오르지만 test는 epoch 4 이후 떨어지고, SearchQA도 selection best가 유지되는 동안 test가 조금씩 내려감
  - LiveMathematicianBench는 epoch당 학습 과제가 35개일 만큼 분할이 작아, 엄격한 게이트도 작은 selection 분할에 과적합할 수 있음

- **비교 조건의 차이**
  - 기준 방법의 최적화 예산(rollout 수, optimizer 모델, 반복 횟수)이 보고되지 않았고, SkillOpt 학습에는 벤치마크당 20.8M에서 213.8M 토큰이 쓰임(Table 6)
  - 벤치마크마다 마련한 사람 스킬의 작성자와 작성 과정이 설명되지 않았고, TextGrad와 GEPA는 direct chat에서만, EvoSkill은 harness에서만 비교해 같은 칸에서 모든 방법을 비교하지 않음

- **"적은 편집"이라는 서술**
  - 수락된 편집 1회에 원자적 편집이 최대 $$L_t$$개 포함되고, OfficeQA는 한 번의 수락으로 스킬이 145에서 883 토큰으로 늘어 변화의 크기는 편집 횟수보다 큼
  - 추론 때 추가 모델 호출은 없지만 최대 약 2,000 토큰의 스킬이 매 호출 문맥에 더해짐

- **optimizer 지식의 유입**
  - 기본 optimizer가 GPT-5.5라, 작은 목표 모델의 이득에는 강한 모델의 절차 지식이 스킬로 옮겨진 부분이 섞일 수 있음
  - 목표 모델과 같은 optimizer 실험(Table 5)은 두 벤치마크와 두 목표 모델에 한정되어, 루프 자체의 기여를 일반화하기에는 범위가 좁음

- **적용 범위**
  - 자동 채점기와 held-out 분할이 있는 과제에 맞춰져 있고, 저자들도 주관적이거나 채점 비용이 큰 개방형 과제에는 더 강한 평가가 필요하다고 인정
  - 도메인마다 스킬 하나만 최적화해, 서로 다른 절차가 많은 이질적 도메인에서는 스킬 라이브러리가 필요할 수 있음

- **계보 안에서의 위치**
  - 궤적 반성과 텍스트 편집은 Reflexion, TextGrad, GEPA가 이미 보인 것이고, SkillOpt의 새로움은 개별 요소보다 편집 폭 제한, 엄격한 게이트, 기각 기억, epoch 단위 정리를 스킬 문서라는 지속 산출물에 묶은 조합에 있음
  - 저자들이 제시한 후속 방향(스킬 라이브러리, meta skill 재사용, 보상 없는 게이트, 스킬의 가중치 증류)은 이 계보의 강화학습 결합 갈래(SkillRL, Skill-Pro)와 맞닿음
